Hook tab lain (live, mudah dibaca)

Seperti Postman, untuk endpoint yang memakai enkripsi sekali pakai per-request (ECDH ephemeral) — curl lama tidak bisa dipakai ulang walau header lengkap, karena kuncinya hanya hidup sesaat di memori tab asli. Pasang skrip ini di tab aplikasi target; panel kecil muncul di sana dan mencatat tiap request apa adanya saat Anda memakai aplikasinya seperti biasa: payload sebelum dienkripsi (hasil sadapan crypto.subtle.encrypt), apa yang benar-benar dikirim lewat jaringan, dan hasil dekripsi response-nya.

  1. Buka tab aplikasi target, tekan F12 → tab Console, tempel skrip di bawah lalu Enter.

  3. Panel muncul di pojok kanan bawah tab target. Tiap request tercatat otomatis; klik ✕ di panel untuk berhenti.

Tes Rate Limiter (dari curl)

Seperti Postman, khusus untuk cek rate limiter. Tempel curl satu endpoint (mis. login atau search), tentukan jumlah & jeda, lalu pasang skrip di tab aplikasi target — sama prinsipnya dengan tab Hook, supaya request jalan same-origin (cookie sesi ikut otomatis, tidak kena CORS). Skrip mengulang request itu berkali-kali dan melaporkan status/waktu/header Retry-After tiap percobaan. Pakai hanya pada sistem yang Anda berwenang menguji; ini mengirim trafik sungguhan berulang.

Opsi 1 — Hit langsung dari halaman ini

Paling simpel, tidak perlu tempel skrip ke tab lain. Jalan selama server mengizinkan CORS dari origin halaman ini; kalau tidak, pakai Opsi 2 di bawah. Cookie sesi browser tidak ikut terkirim dari sini (beda tab/origin) — cocok untuk endpoint yang otentikasinya lewat header seperti API key/Bearer token yang sudah ada di curl.

Opsi 2 — Skrip di tab aplikasi target

Kalau Opsi 1 diblokir CORS atau butuh cookie sesi, pasang skrip ini di tab aplikasi target (seperti tab Hook): jalan same-origin, cookie ikut otomatis.

Panel di tab target muncul di pojok kiri-bawah (supaya tidak bertumpuk dengan panel Hook di kanan-bawah), dengan tombol stop dan salin CSV di sana juga.

Tes RTO — kirim body lambat (slow request)

Menguji apakah server menerapkan request read timeout: body request dikirim menetes pada laju yang Anda atur (mis. 8 kbps). Kalau server menunggu data terlalu lama, ia menutup koneksi — itulah RTO yang diukur. Ini satu koneksi lambat untuk diagnostik timeout, bukan membanjiri server. Server yang sehat seharusnya memutus klien lambat (lih. OWASP Slow HTTP / CWE-400 Uncontrolled Resource Consumption); kalau tidak terjadi, koneksi bisa ditahan lama — temuan hardening. Pakai hanya pada sistem yang Anda berwenang menguji.

Perkiraan durasi kirim {{ rtoEta }} per request (payload {{ rto.sizeKb }} KB pada {{ rto.kbps }} kbps). Metode harus berbody (POST/PUT/PATCH/DELETE); selain itu otomatis dipakai POST.

Opsi 1 — Hit langsung dari halaman ini
